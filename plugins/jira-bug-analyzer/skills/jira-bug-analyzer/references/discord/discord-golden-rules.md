# Discord golden rules

> Moved verbatim from `references/golden-rules.md` in v1.15.3 (P5) so non-Discord runs never load them. Summary lines stay in the SKILL.md tag table.

- **`[DISCORD-DEFER]` Opt-in Discord bidirectional defer — ping đúng role khi defer + reply trên Discord để resume.** Mặc định OFF (giống `--discord`). Bật bằng flag `--discord-defer` HOẶC env `JIRA_BUG_DISCORD_DEFER=1`. **OUTBOUND:** mỗi lần `auto-plan-pick.md` step 2 (atomic Jira+Discord, v1.10.1) post Jira comment xong, step 2.b BẮT BUỘC gọi `references/discord/discord-notify-defer.md` để bắn 1 message vào channel `#jira-bug-analyzer` (defer_channel_id trong `assets/discord-roles.json`) mention `<@role_user_id>` — LLM pick role `{po, dev, qa}` dựa context bug (default `dev`). Message **copy nguyên văn Jira comment body** (đồng nhất 1 source) + append option list (plan A/B/C + custom + command đặc biệt — "Reply để thực hiện action"). Jira vẫn source of truth; Discord là chuông đánh thức, NON-BLOCKING về fail (curl fail → log, defer flow vẫn thành công) nhưng KHÔNG non-blocking về skip (opt-in bật mà bỏ step 2.b = vi phạm spec).

**INBOUND v1.14.0 (multipurpose — tất cả tình huống qua Discord):** v1.11.x bot ghi file inbox + `nohup claude -p` → invisible. v1.12.x inline Phase 3-6 → block manager loop. v1.13.0 Agent background subagent → visible + non-blocking, nhưng CHỈ xử lý ticket-key prefix (regex `/^[A-Z][A-Z0-9]+-\d+\s/`) — reply không có key (`resolve conflict các PR`, `PR nào review?`, `đây là log cho AAP729-5`) bị bỏ qua. **v1.14.0 (breaking từ v1.13.0):** mở trigger thành `@claude` mention HOẶC reply-quote vào bot message. Classifier LLM phân 5 intents (ticket-resume, bulk-op, query, chat/context, meta-cmd) chạy inline trong Job G → routing table trong `references/discord/discord-classifier.md`. Destructive (bulk-op + meta-cmd stop/pause/cancel/clear) qua safety gate 60s TTL — `references/discord/discord-safety-gate.md`. Tất cả intents spawn Agent background subagent (consistency v1.13.0); chat/context + non-destructive meta-cmd chạy inline. Thread context load last 20 msg qua Discord REST, cache 5 min. Open authz: bất kỳ guild member tag `@claude`; destructive luôn gated. Dedup: `mv` atomic (first-come-first-serve 2 máy). Full specs: `references/discord/discord-classifier.md` (intent taxonomy + routing), `references/discord/discord-safety-gate.md` (60s confirm flow), `references/discord/discord-resume-handler.md` (ticket-resume branch), `references/phase-manager-mode.md` → Job G (consumer orchestrator).

**Bot repo coordination (BREAKING):** `claudecode-discord` bot phải update handler forward message khi `(a) @claude mention HOẶC (b) reply-quote vào tin nhắn bot authored` — không chỉ ticket regex nữa. Script `assets/discord-inbox-write.sh` nới `--ticket` optional + thêm `--trigger-type`, `--thread-id`, `--referenced-ticket`, `--referenced-message-id`. Nếu bot chưa update, plugin v1.14.0 KHÔNG nhận event. Config song song: remove `#jira-bug-analyzer` khỏi `learn-app` bot `ALLOWED_CHANNELS` (2 bot cùng react gây conflict — observed AAP729-3 2026-10-19).

**Bot repo coordination:** claudecode-discord bot (repo riêng `~/Desktop/src/claudecode-discord`) phải update handler để invoke `assets/discord-inbox-write.sh` thay cho spawn Skill cũ — nếu chưa update, bot vẫn chạy flow v1.10 (có tool-use trong Discord). Plugin v1.11 chỉ cover plugin side; bot side cần sửa code riêng.

- **`[DISCORD-TICKET-STATUS]` v1.12.2+ — Status ping-back cho MỌI thay đổi trên ticket Discord-triggered.** Mỗi ticket có ledger `discord_defer_enabled: true` (= originated từ Discord qua Job G hoặc defer post ở `auto-plan-pick.md`) → MỌI state change (Phase 3/4/5/6 milestone, PR review comment arrive/addressed, PR merge/close, Jira reopen, new comment arrive, defer lại) PHẢI post 1 status update vào `defer_channel_id`. User gõ reply xong là chờ hồi âm **cho tới khi ticket đóng**; im lặng giữa chừng = fail UX. Full spec: `references/discord/discord-notify-ticket-status.md` (template per-trigger, emoji mapping, retry rules). Non-blocking về fail (log + skip, flow chính không ngắt), nhưng BẮT BUỘC khi điều kiện bật (`discord_defer_enabled: true` + token set + roles.json OK) — skip khi điều kiện đủ = vi phạm spec. Rate limit 5-7 msg/ticket/session chấp nhận, không batch.

- **`[DISCORD-MENTION]` v1.14.1+ — Mention Discord CHỈ dùng `<@USER_ID>` (user mention), CẤM `<@&ID>` (role mention).** `assets/discord-roles.json` chỉ chứa **user IDs** (xem `_doc` field) — plugin KHÔNG có role ID nào. Dùng `<@&user_id>` → Discord không tìm thấy role với numeric ID đó trong guild → render ra **`@unknown-role`** (dev không biết ai được ping, mất tín hiệu). Áp dụng cho MỌI message post Discord: `discord-notify-defer.md`, `discord-notify-ticket-status.md`, `pr-discord-review-request`, Job G ack reply, custom status update LLM tự compose. Nếu không cần ping ai cụ thể → BỎ mention hẳn, KHÔNG thay bằng `@qa` / `<@&qa>` plain text / role NAME. Lookup `USER_ID` numeric từ `roles[po|dev|qa]`, paste nguyên — KHÔNG hard-code / bịa / dùng role name. Bash grep guard trước curl POST: `grep -q '<@&' $CONTENT` → abort. Full spec + guard: `references/discord/discord-notify-defer.md` + `references/discord/discord-notify-ticket-status.md` section *"Mention format (BẮT BUỘC)"*.

- **`[DISCORD-MULTIPURPOSE]` v1.14.0+ — `--manager` xử lý TẤT CẢ tình huống qua Discord.** Trigger: `@claude` mention HOẶC reply-quote vào bot message. Classifier LLM (inline Job G) phân 5 intents (ticket-resume / bulk-op / query / chat / meta-cmd) → routing table trong `references/discord/discord-classifier.md`. Destructive (bulk-op + meta-cmd stop/pause/cancel/clear) BẮT BUỘC qua safety gate 60s TTL (`references/discord/discord-safety-gate.md`); non-destructive dispatch thẳng. Spawn Agent background subagent cho ticket-resume/bulk-op/query (consistency v1.13.0); chat + non-destructive meta-cmd chạy inline. Thread context load last 20 msg qua Discord REST, cache 5 min. Open authz (bất kỳ guild member) nhưng destructive luôn gated. Dedup: `mv` atomic 2 máy. Confidence < 0.7 → clarify branch (reply options, không dispatch). Metrics tracked trong `.jira-bug/active-resumes.json` (`intent`, `confidence`, `token_estimate`) để monitor cost. Skip toàn bộ nếu env `JIRA_BUG_DISCORD_DEFER` unset. **Bot repo (`claudecode-discord`) phải update handler cho mention+reply triggers trước khi plugin v1.14.0 nhận event** — nếu bot vẫn chạy v1.13.0 regex-only, Job G không trigger. Full specs: 2 helpers mới (`discord-classifier.md`, `discord-safety-gate.md`) + `phase-manager-mode.md` → Job G.

**INBOUND v2a (realtime chat, centralized bot pattern):** 1 máy (admin team) chạy claudecode-discord với `ALLOWED_USER_IDS` = team whitelist. Dev / PO / QA bất kỳ reply trong channel → Discord Gateway WebSocket push `MESSAGE_CREATE` event <200ms → claudecode-discord forward vào Claude session <500ms → session chạy `references/discord/discord-resume-handler.md`: detect ticket key regex `[A-Z][A-Z0-9]+-\d+` → check ledger `analyzed-deferred` (`[BGMEM]`) → **LLM intent classification** (ack / context Q&A / resume / review / context push) → ack reply trong 2-8s qua Discord REST, nêu rõ *"Hiểu là: {intent}"*. **Q&A** đọc ledger + Jira trả lời inline. **Resume/Review** post Jira `@claude {body}` → máy dev's `--manager` tick resume ở lần kế (≤10 min). **Context push** (attachment / log) save vào `.jira-bug/discord-attachments/<KEY>/` qua BGMEM. **Resolve ping (Job F `[DISCORD-DEFER]`):** khi dev's Phase 6 open PR + ghi `pr_url` vào ledger (`phase6-commit-pr.md` step 3b), central bot's `--manager` tick phát hiện → POST *"✅ Resolved {KEY}: {PR link}"* vào channel — xem `references/discord/discord-resolve-watcher.md`. Lý do split central / dev: realtime chat ở central (có Gateway), fix execution ở dev (git/jira creds + worktree). **Config:** `assets/discord-roles.json` (role map + channel ID — public IDs, không secret) + env `LEARN_APP_DISCORD_BOT_TOKEN` trong `~/.claude/settings.json` (bot token, share với learn-app plugin — chỉ REST, không mở gateway thứ 2). **Caveat share token:** nếu learn-app sau này mở gateway listen replies, hai process sẽ đá nhau — khi đó tạo bot thứ 2 riêng.
