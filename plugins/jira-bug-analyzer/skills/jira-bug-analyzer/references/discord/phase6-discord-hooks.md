# Phase 6 — Discord hooks (`[DISCORD-DEFER]`)

> Loaded by `references/phase6-commit-pr.md` step 3b only when the ticket's ledger row has `discord_defer_enabled: true` or the run carries `--resume-from-defer`. Moved out of the core Phase-6 file in v1.15.3 (P5) so runs without Discord never read it. Text unchanged.

3b. **`[DISCORD-DEFER]` resolve hook** — nếu ticket có ledger row với `discord_defer_enabled: true` (defer trước đó qua `--discord-defer`): sau khi PR open thành công, update ledger row (`[BGMEM]`) → set `pr_url: <link>` + `resolve_posted_to_discord: false`. Job F trong `--manager` (xem `references/discord/discord-resolve-watcher.md`) sẽ pick up và post *"✅ Resolved: {PR link}"* vào Discord channel ở tick kế. Non-blocking: ghi ledger fail → log + continue, không block PR flow.
3c. **`[DISCORD-DEFER]` push-mode inline post (v1.10+)** — *(từ v1.15.3 `--resume-from-defer` dừng sau Phase 3 nên không còn tới bước này; ticket resume được sửa ở single mode và Job F lo post Resolved. Giữ mục này cho tương thích.)* Nếu run invocation có flag `--resume-from-defer` (session được spawn bởi Discord handler, xem SKILL.md Mode dispatch rule 3b): BYPASS Job F, post thẳng Discord ngay sau PR open. Lý do: push mode đã promise dev "ETA 5-30 min" ở Discord ack — không nên chờ thêm --manager tick. Steps: (a) build message *"✅ Resolved **{KEY}**: {PR_URL}\n{summary}\nChangelog: {PR title}"*. (b) POST qua Discord REST vào `defer_channel_id` (`assets/discord-roles.json`) + verify 200/201. (c) Set ledger `resolve_posted_to_discord: true` + `resolve_posted_at: <ISO>` NGAY (`[BGMEM]`) — Job F thấy flag → skip, không duplicate. (d) **Cleanup `.jira-bug/active-resumes.json`**: xoá entry cho `<KEY>` (push session hoàn tất, dedup lock giải phóng). (e) Non-blocking: fail POST → log + Job F sẽ cover ở tick kế (flag chưa set).
