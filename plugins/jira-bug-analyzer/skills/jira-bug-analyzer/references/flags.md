# Flags, usage and phase resolution

> Moved verbatim from SKILL.md in v1.15.3 (P4) so the router stays small. Read it when an invocation carries a flag you need the full rule for. Numbers live in `references/constants.md`.

> **Phase resolution (`@N`) — which `<PHASE>/doc/` + `<PHASE>/session/` + `phaseX/` branch prefix this run uses.** A bare `@N` token in the args (e.g. `@3`) sets **`phase = phaseN`** explicitly — this WINS over everything. If no `@N` is given, the phase is **derived from the spec's own title** at the Source-of-truth capture (Phase 2): the `source-of-truth` subagent reads the Confluence page title(s)/parent (e.g. a "Phase 3 / Sprint 3 / Milestone 3" marker) and uses that phase. Only if neither an `@N` arg nor a phase-bearing spec title exists → fall back to `phase1`. **Never silently default to `phase1` when the spec title says otherwise** — a wrong phase folder splits memory and dedup. If `@N` and the spec title disagree, honor `@N` but surface the mismatch. Strip the `@N` token before mode resolution — it is orthogonal to single/multi/team, as are `--spec <url>` / `--figma <url>` / `--rediscover` (strip them too; they are Phase-2 inputs, never a mode or a board). **When no `@N` is given, Phase 2 may also DERIVE a phase from the picked tickets' `fixVersions`/sprint/labels — but only to TARGET discovery (enabling the L3a/L3b rungs); the authoritative `<PHASE>` is still confirmed from the found spec's title** (`references/phase2-source-of-truth.md` → the chicken-and-egg section).
> **Usage:** `/jira-bug-analyzer <PROJECT_KEY>` (multi on that board) · `/jira-bug-analyzer <PROJECT_KEY> @N` (multi, phase N — e.g. `AIP686 @3`) · `/jira-bug-analyzer <TICKET-KEY> [@N]` (single) · `/jira-bug-analyzer --google-sheet <SHEET_URL> --project <KEY> [@N] [--auto]` (**multi on a Google Sheet board** — `[SHEET]`) · `/jira-bug-analyzer --team [<PROJECT_KEY>] [@N]` (team) · `/jira-bug-analyzer --manager <PROJECT_KEY> [@N] [--auto]` (manager mode — PR review comments + worktree cleanup + KB-backfill; one pass per run — run it after QA verifies a batch; add `--loop [interval]` for a recurring in-session loop) · `--repro` (**opt-in on-device repro** — default OFF; see Golden Rule `[REPRO]`; NL intent like "tái hiện trên máy" / "reproduce it on device" also turns it on, negation-aware) · `--discord` (opt-in Discord PR-review posting, any mode incl. `--auto`) · `--resume` (reconcile) · `--spec <url> --figma <url>` (override the auto-resolved source-of-truth; normally unnecessary — `/jira-bug-analyzer AIP686 @3 --auto` resolves the phase + its spec/figma from Jira on its own). Always pass the resolved project key to the init script as `--project <KEY>` so it can resolve setup local→remote.
> **Flags:** `--repro` (**opt-in device repro — see Golden Rule `[REPRO]`**: turns `[REPRO_ON]=true`, enabling Fix-5.5 A4–A6 on-device repro + A8–A10 can't-reproduce ladder. **Default is OFF** — Fix-5.5 runs only A1–A3 reality-check + static trace from media/code; the Fix-6 block carries `Reproduced: skipped (no --repro)` + `not device-verified`. The main loop ALSO detects NL intent in the user's request as implicit `--repro` — triggers `reproduce`, `repro`, `test on device`, `on-device`, `tái hiện`, `kiểm tra trên máy`; negation-aware (`can't`, `không`, `without`, `skip` within 10 chars before the trigger cancels it). Under `--auto`, `--repro` restores the hard-require (device-or-defer) at `AUTO_THRESHOLD_REPRO`; without `--repro`, `--auto` runs at `AUTO_THRESHOLD_DEFAULT` (`references/constants.md`) and no device dependency at analyze time. Phase 5 still attempts on-device verify by default and fails-open to static verify + `not device-verified` flag if no device is available). `--auto` (**fully-autonomous loop — see Golden Rule `[AUTO]`**: auto-pick (`auto-ticket-pick.md`) → auto fix-vs-defer by confidence (`auto-plan-pick.md` — threshold `AUTO_THRESHOLD_LOW` with `--auto-low` + LLM `[LOW-RISK-GATE]`, else `AUTO_THRESHOLD_REPRO` with `--repro`, else `AUTO_THRESHOLD_DEFAULT`; behavioral tickets defer under `AUTO_SCOPE=ui-only` — `references/constants.md`) → `code-reviewer` + the verifier subagent (`android-ui-verify` UI / `android-self-verify` behavioral) as the gate, 5× verify retries (`auto-run-test.md`) → **auto commit+PR in a background Phase-6 agent (Discord OFF unless `--discord`)** → **loop back to Phase 1 and repeat until the board is empty** → end-of-run report; `<threshold`/clarify-gap/blocked tickets are parked + reported, never guessed; PRs opened but never merged; **the inline PR watcher is NOT armed — review-comment handling + worktree cleanup + KB-backfill are handled by `--manager`, run it after the batch**. Default OFF = every gate interactive). When used with `--manager`, `--auto` governs Job A only (auto-apply unambiguous review fixes; Job C KB-backfill is unattended regardless). `--manager` *(the 3rd mode — manager mode: PR review comments + worktree cleanup + KB-backfill; runs ONE pass and stops; `--loop [interval]` opts into a recurring in-session loop (`MANAGER_LOOP`); see `references/phase-manager-mode.md`)*. `--pr-window <N>m` (**removed in solo modes** — review is per-ticket & streamed the instant each fixer is green, no windowed round; warn+ignore if passed. **`--team` still cuts rolling PR rounds** — `TEAM_PR_ROUND` in `references/constants.md`, `team/team.md`). `--discord` (**opt-in Discord PR-review posting, any mode**: enqueue each opened PR to the *Apero Mobile Developer / review-pr* channel via `pr-discord-review-request`, Phase-6 Step 3. In **interactive** modes it turns the always-asked *"Post review request to Discord?"* prompt into auto-yes — skip the ask, always enqueue. Under **`--auto`** it is the ONLY way to post — the default is Discord OFF; `--discord` makes the background Phase-6 agent enqueue the PR after opening it. Best-effort — needs `PR_DISCORD_CHANNEL_URL` (`.claude/.env`); unset under `--auto` → log to report + skip, never block the loop. Interactive without the flag is unchanged: still asks, default Y). `--auto-low` (**compose with `--auto` only — lower the auto-approve threshold floor to `AUTO_THRESHOLD_LOW` (`references/constants.md`) so plans AI currently over-defers (reasonable + low-risk, just low confidence score) get fixed; adds a mandatory `[LOW-RISK-GATE]` LLM pass as the second rail (reasonable + low-risk? pass/fail — fail → defer `low-risk-check-failed`, no retry); verify flow unchanged (adb self-verify + retry budget 2 per `auto-run-test.md`); every fix carries BOTH Jira labels `auto-fixed` + `auto-fix-low` so Manager Job D tracks reopen-rate separately. Composable with `--repro`. See Golden Rule `[AUTO]` + `references/helpers/auto-plan-pick.md`**). `--model <opus|sonnet|haiku>` (override the per-stage matrix, all modes). `--google-sheet <SHEET_URL>` (**board SOURCE = a link-shared Google Sheet instead of the Jira board — Golden Rule `[SHEET]`, spec `references/google-sheet-board.md`**; composes with multi/team, never single; the parsed rows cache in `setup.json` local+remote and refresh each turn; status saved to the ledger, the sheet is never written; needs `--project <KEY>`). **`--spec <url>` / `--figma <url>`** (**OVERRIDE the phase's source-of-truth — any mode. Not normally needed**: with `@N` the §2.0 ladder resolves the spec from Jira itself (L2d/L2e/L2f). Reach for these to correct a wrong adoption, or for a project whose Jira genuinely carries no link anywhere. Each is adopted by Phase 2 §2.0 as the **L0.5 rung**: highest priority, **STRONG, zero prompts**, beating the L1 `sotByPhase` cache and every detection rung. Adopting persists it to `sotByPhase[<PHASE>]` (local + shared, `[BGMEM]`) so it is a **one-shot seed** — later runs of the same phase inherit it via L1 and need neither the flag nor an ask. Supply either or both; the one you omit still goes through normal detection. Pair with `@N` to be explicit about which phase you are seeding. Combine with `--rediscover` to overwrite a wrong cached entry). `--rediscover` (force a fresh §2.0 detect: skip the L0 `metadata.json` + L1 `sotByPhase` short-circuits and re-walk the ladder from L2 — use when the spec page moved or a wrong page was adopted). `--recheck-env` (force a fresh env preflight, ignoring the cached `env` block — passed through to the init script). `--prune <PROJ>` (a modifier, any mode: clear that project's session memory `project/<PROJ>/*/session/` — the `record_bug_status.md` ledger — when a phase closes; doc/source-of-truth, setup, and KB are untouched; via the `memory-keeper` agent — a whole-file prune; per-ticket rows are only ever written by `assets/ledger.sh`). `--every` is removed — multi re-pulls automatically each turn; warn+ignore if passed.
